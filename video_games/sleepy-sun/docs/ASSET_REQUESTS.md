# Art still to draw

The project is stripped to one minigame, so this list is short. Everything here
currently ships as a **generated placeholder** and the game is fully playable
today. Replacing one is a straight file swap: same path, same dimensions, no
code change.

Generated by `tools/make_placeholders.py`. Its `KEEP` set lists exactly what the
stripped project wants, so re-running it cannot resurrect art for a parked game
— but it **will overwrite** these paths. Once real art is in place, take that
path out of `KEEP`.

Palette the placeholders use, if you want real art to sit alongside the rest
before it is all replaced:

| Role | Hex |
|---|---|
| Deep water | `#224C70` |
| Mid water | `#2E648D` |
| Foam | `#B0D6E8` |
| Grass | `#4A7A3C` |
| Warm light / sun | `#FFD166` |
| Ink / outline | `#1C1A26` |

## Priority 2 — the player

| Path | Size | Frames | Notes |
|---|---|---|---|
| `assets/game/player/idle_up.png` | 32×32 | 1 | **The only genuinely missing player art.** Currently frame 0 of the up-walk held still. Back view, standing — and it is what you look at most, since the character turns upstream between hops. |
| `assets/game/player/jump_{down,up,left,right}_{0,1,2}.png` | 32×32 | 12 | Crouch, airborne, land — for each facing. **These are derived, not drawn.** `player_jump_frames()` in `tools/make_placeholders.py` cuts the matching `idle_*` frame into bands at the skirt hem and *moves* them; it does not resample, because at this size the legs are four pixels tall and scaling dissolves them. That is exactly what the first attempt did, and the character read as a legless smear. Two rules if you redraw the player: the legs must stay **visible below the skirt** in the airborne frame (hiding them behind it is what broke it), and the skirt should lift — at 32×32 the skirt is most of the silhouette, so a flaring hem sells the jump where moving the legs cannot. Regenerate these rather than hand-editing them. |
| `assets/game/player/walk_left_0..3.png` | 32×32 | 4 | **Not a mirror of the right-facing set, and missing its stride** — the legs stay together in all four frames while `walk_right_*` strides in three. The jump works around this by posing from the right set and mirroring it, so nothing is broken; but until these are redrawn, left-facing *walking* would look wrong in any future game that uses it. |

The jump is **posed in code**, not drawn: squash, stretch, lean, and a landing
squash applied to the walk frames. No jump sprites are needed. If you redraw the
player, keep the 32 × 32 canvas with the feet on the bottom edge — the 1.5×
scale is applied in `src/core/player.tscn`, not baked into the art.

## Not art, but worth knowing

- **Fonts are done.** Press Start 2P and Pixelify Sans, both OFL, with their
  licences, in `assets/game/fonts/`. Two constraints if you restyle: Press Start
  2P is about twice the width of a normal face, so columns are tight everywhere;
  and **Pixelify Sans is unreadable below 11 px**. All text goes through
  `src/ui/game_theme.tres` — change it there, not per label.
- **Art for the seven parked games is not deleted**, it is in `main` at
  `876d449`. It comes back with its game, one at a time.
